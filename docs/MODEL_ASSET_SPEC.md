# 3D model asset specification

The studio loads **glTF 2.0 binary (.glb)** files. The two placeholder rings in `web/public/models/` were generated by
`server/scripts/generate-placeholder-glb.js` and follow this same contract, so real assets drop in with no code changes.

## What "real asset" means in this product

A configuration is shown as **Real 3D model** only if *both* are true (see `describeSupport` in `server/src/services/pricing.js`):

1. the design has an `assetVariants` entry whose `stoneShape` equals the customer's chosen shape, and
2. the chosen metal key is listed in `assetBackedMetals`.

Everything else is labelled **Simulated preview**, with the specific simulated features listed. Never list a
shape or metal as asset-backed unless a modeller has verified it.

Manufacturing status (`concept` → `cad_ready` → `approved_for_manufacturing`) is independent of the 3D asset and is only
changed through the admin "Manufacturing" action, which is audited (`approvedBy`, `approvedAt`).

## File requirements

| Item | Requirement |
|---|---|
| Format | `.glb`, glTF 2.0, one scene |
| Units / scale | 1 unit = 10 mm. A ring is ≈ 1.8 units across. Origin at the centre of the piece, +Y up |
| Orientation | Ring band axis along **Z** (finger hole facing the camera), stone on +Y |
| Triangles | **≤ 120 k** for the high LOD; ≤ 40 k mid; ≤ 12 k low (`lodUrls.low`) |
| File size | ≤ 3 MB high LOD, ≤ 1 MB low (after compression) |
| Compression | Draco **or** meshopt geometry compression. Draco decoder is fetched by drei only when needed |
| Textures | None required. Metals and gems use runtime PBR materials. If baked maps are supplied: KTX2/Basis, max 2048², max 2 maps per material |
| Materials | Ignored at runtime and replaced by the studio's materials, so author with neutral PBR. Keep ≤ 3 materials |
| Normals | Metal: smooth normals. **Stones: flat (per-facet) normals** so facets catch light |
| Cameras / lights | Do not include |

## Node and mesh naming

Mesh names drive material assignment, exploded view and measurements.

| Name | Purpose |
|---|---|
| `stone`, `gem*` | Treated as gemstone → diamond/gem material. Anything else is metal |
| `band`, `head`, `shank`, `prong*`… | Metal parts; any name is allowed |

Names must match the `components[].meshName` / `annotations[].meshName` values stored on the design.

## Optional features (only enable when the asset really supports them)

**Exploded view** — set `model3d.explodedView = true` and list `components`. Each component mesh may carry a glTF
extra `{ "explode": [x, y, z] }` (units as above). Without it, parts fan out upward in list order (0.4 units apart).
When `explodedView` is false or `components` is empty, the Exploded and highlight controls are **not rendered**.

**Measurements** — `model3d.annotations: [{ label, meshName, valueMm }]`. The label anchors to the top of that mesh's
bounding box. `valueMm` is authoritative; it is not measured from the mesh. The Measure button only appears when
annotations exist.

## Design record example

```json
{
  "model3d": {
    "primaryGlbUrl": "/models/aurelia-round.glb",
    "assetVariants": [
      { "key": "round", "stoneShape": "round", "glbUrl": "/models/aurelia-round.glb",
        "lodUrls": { "low": "/models/aurelia-round-low.glb", "mid": "/models/aurelia-round-mid.glb" } },
      { "key": "oval",  "stoneShape": "oval",  "glbUrl": "/models/aurelia-oval.glb" }
    ],
    "assetBackedMetals": ["yellow-18K", "white-18K", "rose-18K", "platinum-950"],
    "explodedView": true,
    "components": [
      { "id": "band", "label": "Band", "meshName": "band" },
      { "id": "head", "label": "Prong head", "meshName": "head" },
      { "id": "stone", "label": "Centre stone", "meshName": "stone" }
    ],
    "dimensionsMm": { "width": 18, "height": 22, "depth": 18, "bandWidth": 2 },
    "annotations": [{ "label": "Band width", "meshName": "band", "valueMm": 2 }]
  },
  "simulated": [],
  "manufacturing": { "status": "cad_ready" }
}
```

Set `simulated: ["model-proxy"]` while a design still uses a generic placeholder shape; the UI then says so.

## Delivery checklist for a modeller

- [ ] Validates with `npx gltf-validator file.glb` with zero errors
- [ ] Compressed (`gltf-transform optimize in.glb out.glb --compress draco` or `meshopt`)
- [ ] Triangle and size budgets met for each LOD
- [ ] One GLB per stone shape you claim as real
- [ ] Mesh names match the design record
- [ ] Stones have flat normals, metals smooth
- [ ] Checked in the studio at all three quality levels (Quality selector, bottom-right of the viewer)

## Rendering budget (implemented in `web/components/studio/quality.js`)

| Tier | Pixel ratio | Diamonds | Shadows | Chosen when |
|---|---|---|---|---|
| high | ≤ 2 | mirror facets + thin-film iridescence | contact shadows 1024 | capable desktop |
| medium | ≤ 1.5 | mirror facets | contact shadows 512 | phones/tablets, ≤ 4 GB / ≤ 4 cores |
| low | 1 | standard metallic material | none, no MSAA, low LOD | software GPU, ≤ 2 GB / ≤ 2 cores, Save-Data |

The tier is detected at load and then **downgraded automatically** if `PerformanceMonitor` sees sustained frame drops.
Users can override it from the viewer. The scene renders on demand (no idle GPU use) and the studio lighting is
procedural (no HDRI download).
